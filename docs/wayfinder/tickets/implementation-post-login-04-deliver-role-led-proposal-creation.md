# 04 — Deliver role-led Proposal creation

**Parent:** [PactFlow post-login workspace redesign specification](../post-login-workspace-redesign-spec.md)

**What to build:** A user creates a Proposal in an owning Workspace by choosing “I’m hiring a service provider” or “I’m providing a service,” then naming an exact-email counterparty. The resulting Contract records complementary Buyer and Service Provider responsibilities, stays accessible only to authorised initiating Workspace members until explicitly shared, and uses quiet privacy guidance.

**Blocked by:** 03 — Deliver table-first Workspace Contracts.

**Status:** ready-for-agent

- [ ] Proposal creation requires an owning Workspace and explicit initiating Buyer or Service Provider responsibility.
- [ ] The new Contract records the inverse responsibility for the counterparty without changing either person’s Profile or Workspace authorization.
- [ ] The UI uses Proposal language, provides a single understated privacy explanation, and removes “private draft” and “private Contract” headline/action copy.
- [ ] Authenticated creation tests prove Workspace ownership, responsibility assignment, exact-email invitation behavior, and unchanged unauthorized-access rejection.
